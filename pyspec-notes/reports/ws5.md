### Module layout (Tools/clinic/libclinic/pyspec/)
- **frontend.py, partial_eval.py:** unchanged from WS1.
- **runtime.py:** now also holds the facts vocabulary: CType, char_p, void_p, const_void_p, Py_ssize_t, va_list, pointer, New, Borrowed, Steals, Out, InOut, OnError, NoError, NullIn, RunsPython. Its documentation is a comment block there. This follows D3: the vocabulary sits with the other names a spec imports.
- **capi.py (new, from Tools/pyspec/capi.py):** the catalog checks only. It is a separate module because it is about 1100 lines of readers and checks for headers, C definitions, Doc/c-api, refcounts.dat and the stable ABI data, which don't belong in the runtime.
- **call_table.py (new, from Tools/pyspec/call_table.py):** WS4's call table generator.
- **emit.py:** carries WS4's hook. `Generator.generate()` ends with `out += call_table.generate(self, descriptions)`, so clinic writes the variants and the call table into `Objects/clinic/bytesobject_pyspec.c.h`. There is no separate command.
- **`__init__.py` and `Tools/clinic/mypy.ini`:** now list capi and call_table. Both modules are in the "not annotated yet" relaxed mypy section.
- `Tools/pyspec/` does not exist.

### How the conflicts were resolved
**WS2:**
- capi.py now:
  - imports its vocabulary from `.runtime`;
  - loads the spec with `runtime.load()` instead of its own sys.path loader;
  - uses `frontend.is_stub()` instead of its own stub test (a docstring-only body now also counts as a stub, as the brief says);
  - builds `behavior()` on `frontend.Spec`.
- In `Objects/pyspec/bytesobject.py`:
  - The catalog stubs came out of their `if True:` block and are now top-level functions.
  - They import the vocabulary, including `cstr`, from `libclinic.pyspec.runtime`.
  - The `PyBytes_FromObject.__doc__ = ...` assignment became a real docstring, with the same wrapping as bytes.rst.
- `test_pyspec_catalog.py` imports `libclinic.pyspec.{capi,runtime}` through `test_tools.imports_under_tool('clinic')`, the same way test_clinic does.
- Clinic output did not change. All 42 pinned disconnects still match.

**WS4:**
- call_table.py now takes the `emit.Generator`. Spec names are `bytes.__new__`, and C names come from `generator.c_basename()`, which gives `bytes_new_nargs1_<T>` and `bytes_new_spec_calls`.
- Calls to other spec functions are found with `Spec.call_target()`. A call to a stub is treated as an unknown C function, meaning it may run Python code and its result type is unknown.
- The comments in pycore_pyspec.h and in the generated file now name the new location.
- Removed an unused variable that the ruff pre-commit hook flagged.
- Everything else merged without conflicts: bytecodes.c, optimizer files, generated cases and metadata, template.c, build files, test_opt.
- The regenerated `bytesobject_pyspec.c.h` is byte-identical to WS4's except for two "Generated by" comments.

**Stub rule:** WS1 implemented it. `frontend.is_stub()` treats a body of only a docstring and/or `...` as a stub, `implemented_functions()` skips stubs, and emit only lowers implemented functions. I added a note about this to emit's docstring.
