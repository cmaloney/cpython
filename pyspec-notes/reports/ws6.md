# WS6: achievable pyspec speedup for bytes calls (micro, startup, pyperformance)

(Saved by coordinator from the WS6 agent's returned text; raw data in this directory.)

Interpreters (PGO+LTO, main ee1bbf037ff): base = build_perf_base, jit = build_perf_base_jit,
pyspec = build_perf_pyspec (= ws6/pyspec_python_snapshot; pyspec-generated bytes_new +
PyBytes_FromObject, no JIT). Headline numbers are instruction counts (box was busy).

## Bottom line
| scope | achievable with pyspec |
|---|---|
| micro: `bytes(...)` constructors | −23..−25 % instr/stmt measured (225–261 instr/call); cycles −16..−22 % (`bytes(b16)` −5 %) |
| micro: bytes methods | bound 0.3–8 % of stmt; `bytes.fromhex` on the type 29 % (classmethod binding) |
| startup | no measurable effect (≤ 0.03 %) |
| pyperformance end to end | < 1 % everywhere: dulwich_log ≤ 0.7 % (~0.35 % realistic); base64/asyncio_tcp/tornado_http ≤ 0.1 %; bpe_tokeniser 0.04 %; rest ≈ 0 |

Biggest bytes-related lever is not calls: `bytes[int]` subscript has no specialization
(≤ ~2 % on pyflate); slot paths ~2.8 % dulwich_log, ~4.3 % pickle_pure_python (`+=`).

## 4. Blockers pyspec cannot touch
1. Interpreter dispatch 37–75 %.
2. Refcount + alloc 15–25 %.
3. C extension/library work (binascii, zlib, _pickle, _json, sqlite).
4. Bytes ops through slots, not calls (subscript, ==/hash, +, len) — zero bytes specializations in bytecodes.c.
5. Type dispatch inside impls (60–241 instr/call) → needs per-type entries.
6. JIT adds nothing for bytes calls today (`_CALL_NON_PY_GENERAL`; `bytes.fromhex` allocates a bound method per call).
